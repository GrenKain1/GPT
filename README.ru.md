# FantasyDream

Готовый сайт-каталог для Apache и PHP 8.2 или новее. Сборка Node.js, Composer и SQL не нужны. Основной язык — иврит; русский и английский доступны на каждой странице. Админка — на английском.

## Файлы и размещение

В архиве находятся две соседние папки:

```text
папка аккаунта хостинга/
├── private/       ← PHP-движок, каталог, настройки и файловое хранилище
└── public_html/   ← корень сайта: index.php, CSS, JavaScript и изображения
```

Загрузите содержимое `public_html/` в корень сайта, а `private/` — на один уровень выше, рядом с ним. Каталог `private` должен быть вне публичного корня. Не загружайте весь архив в публичный корень: документация и установочный токен не предназначены для публикации. Название публичной папки может отличаться — PHP ищет `private` в её родительском каталоге. Если тариф запрещает размещение файлов выше корня сайта, обратитесь к поддержке хостинга для отдельного приватного каталога; не переносите секреты в доступную из веба папку.

Включите HTTPS, Apache `mod_rewrite` и поддержку `.htaccess`. Публичные PHP-страницы также отправляют заголовки безопасности. На сервере нужны PHP-модули `json`, `session`, `openssl`, `fileinfo` и `gd`; `mbstring` рекомендуется. Для загрузки нескольких фото установите `upload_max_filesize = 5M`, `post_max_size = 32M`, `memory_limit = 128M` или больше. Не включайте `display_errors` на рабочем сайте.

PHP должен иметь право записи в `private` и `public_html/media/uploads`. Используйте владельца аккаунта и обычные права хостинга; не устанавливайте `777`. Файл настройки с SMTP-паролем должен быть доступен только владельцу/PHP. Сайт сам создаст `private/runtime` и файловый контент. Права `0700`/`0600` подходят для PHP, запущенного от имени владельца аккаунта.

При размещении сайта в обычной URL-подпапке, например `/shop`, оставьте `private` вне публичного корня и задайте в настройках PHP хостинга переменную `FANTASYDREAM_PRIVATE_DIR` с абсолютным путём к ней. Для стандартного размещения двух соседних папок эта переменная не нужна. В установщике укажите полный URL с `/shop`.

## Первая установка

1. Откройте `https://ваш-домен/setup.php`.
2. Откройте `private/setup-token.txt` в файловом менеджере хостинга или в распакованном архиве и вставьте токен в установочную форму. Не передавайте его в URL.
3. Придумайте логин и уникальный пароль длиной 12–72 байта. Пароля по умолчанию нет.
4. Проверьте адрес сайта. Для установки в подпапку укажите её в URL.
5. Сохраните предлагаемый случайный путь администратора в менеджере паролей. Он не публикуется в меню, robots.txt или карте сайта.
6. Нажмите **Install website** и откройте страницу администратора.

После установки токен удаляется, а установщик блокируется. Дополнительно удалите `public_html/setup.php`. Если каталог не записывается, проверьте права и журнал ошибок PHP. Не повторяйте установку путём удаления рабочей конфигурации.

## Управление

В админке доступны товары, размеры и цены в шекелях, публикация/скрытие, порядок товаров, галереи, названия и описания на трёх языках, характеристики и SEO-поля. У товара с одним изображением отображается одна фотография; после добавления других появляется управление галереей.

Главная и контакты редактируются для каждого языка. Общие интерфейсные подписи, тексты страницы конфиденциальности и доступности находятся в **Storefront labels**. Адрес, часы работы, WhatsApp, условия доставки и налоговый статус оставлены для заполнения. Контакты из предоставленной обложки сохранены.

Укажите WhatsApp в международном формате, например `+972…`, только после подтверждения номера. Пока поле пусто, WhatsApp-ссылки скрыты. Налоговый статус **Unknown** не выводит утверждений о НДС. Фотографии JPEG/PNG/WebP проходят проверку и повторное кодирование; SVG и исполняемые файлы загрузить нельзя.

## Заявки по электронной почте

В разделе настроек почты администратора задайте SMTP-сервер, порт, TLS/STARTTLS, логин, пароль, адрес отправителя и получателя. Используйте параметры, выданные хостингом или почтовым провайдером; пароль вводится только на вашем HTTPS-сайте. Сохранённый пароль не выводится в формах и не попадает в экспорт контента. При использовании Gmail обычно нужен отдельный пароль приложения или подходящий SMTP-провайдер.

Порт 587 обычно используется с STARTTLS, 465 — с TLS. Проверка сертификатов не отключается. Адрес отправителя должен быть разрешён SMTP-провайдером; данные посетителя записываются в `Reply-To`, а не подставляются как отправитель. Для собственного домена настройте SPF, DKIM и DMARC у провайдера.

Пока SMTP не настроен, сайт сообщает о невозможности отправки; успешную отправку не имитирует. После настройки отправьте настоящую тестовую заявку и убедитесь, что она пришла получателю. Ответ SMTP об успешном приёме ещё не гарантирует попадание во входящие.

Цены, размер и итог заявки проверяются на сервере по каталогу. Подмена цены в браузере не меняет письмо. Оплата на сайте отсутствует; наличие, доставка и окончательное согласование заказа остаются за вами. Сам сайт не хранит заявки: они находятся в почтовом ящике.

## SEO, данные для поисковиков и доступность

Страницы формируются на сервере и читаются без JavaScript. Настроены языковые URL, `canonical`, `hreflang`, Open Graph, Product/Offer, Organization, BreadcrumbList и карта `/sitemap.xml`. Файл `/llms.txt` кратко описывает каталог и даёт ссылки для систем, которые его поддерживают. Это не гарантия позиций в поиске или ответах ИИ.

Цены размечены в ILS; неподтверждённые наличие, отзывы, сертификаты и рейтинг не добавлены. Домен используется из настройки установщика. При смене домена обновите настройки и проверьте карту сайта.

Есть управление с клавиатуры, видимый фокус, подписи полей, альтернативные тексты изображений, направление RTL, увеличение текста, контраст и уменьшение анимации. Все фотографии имеют размеры в разметке, изображения каталога загружаются отложенно. Сторонних шрифтов, библиотек, счётчиков и трекеров нет. PageSpeed необходимо измерять на вашем рабочем домене; сетевые задержки и скорость PHP зависят от хостинга.

## Каталог и спорные данные

Сохранены 8 моделей и 128 пар размеров и цен из PDF. Описание переведено и отредактировано; неоднозначные общие обещания не используются вместо конкретных характеристик. Перед публикацией проверьте **CATALOG-NOTES.ru.md**: там приведены точные цены и места, которые желательно подтвердить у поставщика. Срок гарантии и гипоаллергенность приведены по исходным материалам производителя.

## Резервное копирование и обновление

Регулярно сохраняйте `private/content.json`, `private/config.local.php` и `public_html/media` за пределами публичного корня. В админке доступен экспорт контента; SMTP-пароль и хеш пароля в него не входят. Для восстановления контента используйте сохранённый JSON через файловый менеджер, сохранив резервную копию текущего файла.

При обновлении не перезаписывайте рабочие `content.json`, `config.local.php`, `runtime` и пользовательские изображения новым дистрибутивом. Новый установочный токен на уже установленном сайте не используется.

## Локальная разработка

Каждая облачная задача уже изолирована; используйте существующий checkout без создания дополнительных Git worktree. PHP 8.2+, Python 3 и Node нужны только для проверок. Установите локально через `php private/bin/install.php --site-url=http://127.0.0.1:8080 --username=admin`; пароль запрашивается без отображения. Запустите `php -S 127.0.0.1:8080 -t public_html tools/router.php`. Это сервер разработки, а не вариант рабочего хостинга.

Проверки: `python3 tests/smoke.py --php /путь/к/php --browser`. Тесты используют временную копию, временный аккаунт и локальный SMTP с проверяемым TLS-сертификатом. Они не отправляют письма вашим клиентам и не меняют рабочие данные.

Сборка дистрибутива: `python3 tools/build_release.py`. Архив создаётся в `dist/`; для него генерируется новый одноразовый токен установки. PHP-конфигурация, сессии и рабочие пароли в архив не включаются.
